## Phạm vi và mức bằng chứng

Trang này phân biệt policy yêu cầu với controls trong source và test evidence. Spring suite có MockMvc/H2 và signed-token unit tests; chưa chạy HTTP service thực, kiểm tra browser cookie/TLS/proxy hay triển khai production. Có Spring Security dependency/config không tự chứng minh endpoint được phân quyền đúng.

## Xác thực và authorization quan sát được

[SecurityConfig](../../spring-web/src/main/java/vn/edu/parking/config/SecurityConfig.java) and [DesktopApiSecurityConfig](../../spring-web/src/main/java/vn/edu/parking/config/DesktopApiSecurityConfig.java) separate Web/session routes from Desktop bearer APIs. The JWT chain is opt-in through `PARKING_JWT_ENABLED` and requires valid external key/configuration; this describes source behavior, not a deployed runtime:

| Matcher / control | Static behavior |
| --- | --- |
| `/login`, static login assets, `/error` | Allowlist |
| `/api/parking/health` | Allowlist in both Desktop-chain states; response exposes status/service only and does not query the database |
| `/api/parking/revenue/**` | Explicitly excluded from the Desktop JWT chain; handled by the Web/session chain and restricted to `ROLE_MANAGEMENT`. Anonymous JSON gets 401, GATE_STAFF gets 403; CSRF stays enabled for unsafe methods |
| Entry/exit/open/lookup/slot view | `MANAGEMENT` or `GATE_STAFF` through stateless Desktop JWT; role is loaded from DB and session/account state is checked |
| Slot mutations and full unassigned vehicles | `MANAGEMENT` only through Desktop JWT |
| `/api/auth/login`, `/api/auth/refresh`, `/api/auth/logout` | Login/refresh are public only when the JWT chain is enabled; logout requires bearer authentication |
| `/api/cccd/**` and `/account-admin/**` | Web/session chain; `MANAGEMENT` only; CSRF applies to mutations |
| `/api/parking/anpr/recognize/image`, `/recognize/video`, `/face/capture`, `/face/verify` under `/api/parking/anpr` | Desktop JWT chain; GATE_STAFF/MANAGEMENT only; bounded request, server-side result/evidence, and internal FastAPI Bearer proxy |
| `/api/parking/sessions/{sessionId}/operations/{operation}/evidence/{evidenceKind}/{evidenceId}/image` | Desktop JWT chain; every path component is checked against an existing parking session and its evidence; GATE_STAFF is limited to its own account/device session and an OPEN session; MANAGEMENT may read any matching gate-evidence object through this business context. Every read is audited; expired unheld or mismatched evidence is hidden. No generic storage/UUID-only route is exposed |
| `/api/**`, `/uploads/**`, `/h2-console/**`, other API paths | Deny unless an earlier explicit matcher allows the route; WebConfig still declares an upload resource handler, but Spring Security denies `/uploads/**` to everyone except MANAGEMENT |
| Other Web pages | `MANAGEMENT` only; `/account/password` allows business roles and the restricted first-login authority |
| Login/logout | Form login backed by DB `SystemAccount`; first-login authority redirects to password change; logout invalidates the Web session and records an audit event |
| User store | `DatabaseUserDetailsService` loads normalized usernames from `system_accounts`; `DelegatingPasswordEncoder` stores `{bcrypt}` at cost 12. Local bootstrap is optional and marks the initial account for password change. No in-memory demo user remains in SecurityConfig |
| Desktop JWT/session | Opt-in RS256/Nimbus encoder/decoder reads signing PEM plus external `PARKING_JWT_VERIFICATION_KEYS_JSON`, issuer, audience and active `kid`. Keyring requires the active key; retiring keys have an explicit `verifyUntil` (and optional `notBefore`), and tokens must fit that window. Decoder validates signature/algorithm, key-pair consistency, timestamps including bounded future `iat`, max 15-minute lifetime and required claims. Stateless API chain derives roles from DB and checks account/session/security version on each request. Login, refresh rotation, logout, reuse detection, idle touch and revoke-all service operations are present. Password changes/resets, disable/enable and role changes lock the account row, increment security version and eagerly revoke stored Desktop sessions in the same transaction. H2 race tests cover self-password change against reset, disable and role change; target-MySQL locking behavior remains unverified. Production key provisioning/rotation remains environment work. |
| Password/account lifecycle | Current password is checked; change/reset/disable/enable/role change increments security version and revokes Desktop sessions. Web requests revalidate enabled/version/role/forced-change state and invalidate stale sessions; database failure fails closed with 503 |
| Account administration/audit | Management-only create/read/enable/disable/role/reset and paged audit endpoints exist. Account reads use allowlists; temporary passwords are returned once on create/reset. Login, logout, password and account lifecycle events are recorded without credentials or hashes |
| Method/object authorization | `@EnableMethodSecurity` and controller method guards are present. Resident entry requires a selected active family member authorized for the vehicle; missing, inactive and unrelated members are rejected. The operational slots API omits owner name, phone and apartment for both signed roles; broader object scoping and response minimization remain incomplete |

The local bootstrap helper is [prepare-security-bootstrap.ps1](../../scripts/prepare-security-bootstrap.ps1). `-Action Prepare` creates a random local credential encrypted with user-scoped Windows DPAPI and a restricted ACL; `-Action Reveal` opens a local retrieval window; `-Action Load` places it only in the current PowerShell process environment. A protected credential record was prepared, but no MANAGEMENT row was created. Do not load/use it until the intended datasource and an approved migration target are verified.

Các route API chưa được đưa vào explicit allowlist bị deny thay vì được mở theo prefix. Desktop API bearer failures trả 401; authenticated role mismatch trả 403 qua Resource Server chain. `/api/parking/revenue/**` được tách khỏi JWT matcher để Thymeleaf dùng Web session; integration tests đi qua actual filter chains và DB-backed login xác nhận Management 200, Gate 403, anonymous JSON 401, và CSRF còn hiệu lực cho unsafe methods. Image/video/face recognition và gate-evidence routes đều dùng Desktop JWT. `/api/cccd/**` và các Web JSON route khác thuộc session chain. `/api/parking/open` uses an allowlisted DTO, lookup no longer returns owner phone, unassigned-session/vehicle responses omit resident name and apartment fields, and `/api/parking/slots` omits assigned owner name, phone and apartment for both signed roles. The Management Web `/slots` page is separate; management member data still includes raw CCCD QR. Broader response minimization remains incomplete. Resident uploads remain a separate Management-only surface. Gate-evidence reads require a specific session, operation, evidence kind and evidence ID; MANAGEMENT role access does not create a generic private-storage download permission.

Đây là **observed source and isolated-test behavior**, không statement về production reverse proxy/firewall, applied migration, provisioned key configuration hay effective runtime datasource. JWT bearer endpoints and per-request session binding are implemented in source and tested with H2/synthetic RSA keys; runtime key provisioning, target MySQL behavior and deployment remain unverified.

## CSRF, CORS, session và HTTP transport

- **CSRF — source observed:** Spring default CSRF protection applies to the Web/session chain and form mutations; the separate stateless Desktop bearer chain disables CSRF and does not use browser cookies. MockMvc mutation tests include CSRF tokens.
- **CORS — source observed:** no explicit CORS configuration was found. Browser same-origin policy applies absent proxy headers/config; deployed behavior is unverified.
- **Headers — source observed:** Spring Security default headers apply and frame options are denied. No explicit CSP is established; HSTS/TLS behavior depends on HTTPS/proxy runtime and is unverified.
- **Session/cookies — source configured:** `application.yml` sets a 30-minute idle timeout, HttpOnly, SameSite Lax and Secure by default (`PARKING_SESSION_COOKIE_SECURE` can override). MockMvc verifies these properties; browser behavior behind the actual TLS terminator is not tested. Web requests revalidate account/session state.
- **Transport — deployment gap:** Desktop defaults to `http://localhost:8080` and `http://localhost:8001`; ANPR camera fetch uses HTTP localhost. TLS termination and trusted proxy settings are unverified. “localhost” is not a deployment boundary if bind/proxy configuration differs.

Stored or returned sensitive categories include citizen IDs/old IDs/raw CCCD QR, full names, addresses, dates, phone/email, registration/face images, plates, entry/exit timestamps and session/payment history. The gate `lookup` retains an empty `ownerPhone` compatibility field and no longer returns the stored phone number; the Desktop operational slots API omits assigned owner name, phone and apartment for both roles, while the separate Management Web slot view remains management-scoped. Management member-data still returns raw CCCD QR. Account administration uses allowlisted read models, but a comprehensive response allowlist/privacy review has not been completed.

Upload observations: ResidentImageStorage accepts multipart or base64, caps 10MiB, requires ImageIO-decodable content and writes original bytes with UUID `.jpg`; extension does not prove re-encoding. Internal reads allowlist the resident UUID reference, reject symlinks and read at most 10MiB. Its default root is outside classpath static resources, and `/uploads/**` requires Management. Gate evidence uses a separate private root, random file references, 10MiB bounds, SHA-256 metadata, 30-day expiry from `capturedAt`, daily deletion of eligible expired/orphan files and finite audited Management holds. ANPR image/video/face routes require internal Bearer auth; FastAPI image/video limits are 10MiB and Spring validates its uploads. Tests cover H2/fake paths only. No encrypted-at-rest, consent record, deployed storage-root, backup/restore, or runtime multipart/proxy evidence is established. Do not infer a broader legal retention period from NV files.

## Face verification, manual override and replay/payment risks

- Entry service checks that the selected family member is active and authorized for the vehicle. When a registered face exists, entry requires recent Spring-owned evidence unless one of the three approved, reasoned exceptions applies: the member lacks a registration reference image; backend-linked face verification is `AI_REVIEW`; or Spring records a recognition-service outage. Each override requires `OVERRIDE_CREATE`, a specific reason, principal-derived actor and operation/session-bound evidence; audit records the exception and evidence reference. AI `REJECT`, a client-claimed result, unauthorized/missing member, and unlisted failures remain denied. Existing card-status, duplicate-open and other business checks still apply. Guest capture remains separate and is bound/consumed at entry when supplied.
- For guest sessions with a stored entry-face image, exit requires a recent `PASS` face proof matching the operation, recognized plate, and open parking session; confirmation consumes it transactionally with exit recognition. Resident exit verification is supported when supplied but is not mandatory for every resident exit. Guest capture remains optional at entry, so a guest session without a stored face image does not trigger this conditional exit check. No liveness/anti-replay effectiveness claim is made.
- Desktop recognition and face/camera requests now use authenticated Spring routes; Spring is the only Desktop processing caller to FastAPI. Evidence IDs and server-stored recognition results are authoritative for entry/exit, while legacy client AI/face fields are not. This is isolated source/H2/fake evidence, not live service/deployment proof.
- If refresh rotation has an ambiguous timeout/network or malformed-response result, Desktop clears the local tokens and requires login again; the failed entry/exit POST is not replayed. Regression tests cover a simulated possibly-consumed refresh and a malformed response, not an offline queue or exactly-once mutation contract.
- ANPR computes a motion score for camera frames, but current route does not return/use it to block successful match. The separate 3-image demo explicitly does not prove liveness gate integration. Spoof/replay resistance is **not established**.
- No idempotency key, nonce, unique request event or expected-state version in entry/exit contracts. OPEN precheck is application check before save; concurrent duplicate and response-timeout replay outcomes are not proven safe. Confirm re-finds an OPEN session; delayed/repeated confirm behavior may be “no open session” after first success, but no stable replay response contract exists.
- Fee calculation and session completion are not payment settlement: no visitor payment confirmation/receipt transaction or payment authorization gate in reviewed exit service. SubscriptionPayment is a separate record created with monthly pass; not per-session settlement evidence. Revenue JSON now uses the Web session chain and is Management-only with H2 integration evidence; revenue calculation/reconciliation correctness and deployed browser behavior remain unverified.
- B1-A supports only the three approved override cases: missing registration reference image, backend-controlled `AI_REVIEW`, and backend-recorded recognition-service outage. Integration tests exercise the missing-image, outage and review paths, including exit review; `REJECT` and unlisted errors fail closed. The Management review listing is audited. This does not waive vehicle/card/session checks or establish live-service behavior.

## Error and abuse-surface observations

- Parking API converts selected `IllegalArgumentException`/`IllegalStateException` to 400 and exposes `ex.getMessage()` in response. Other Spring errors/serialization/binding paths have no single response envelope confirmed.
- CCCD QR maps handled `IllegalArgumentException` validation failures to 400 with the validation message and handled `IllegalStateException` scan failures to 400 with a fixed generic message. Other framework/unhandled errors do not have a uniform response contract established here.
- ANPR `verify-camera` no longer accepts a caller URL; Spring sends a server-read registration image to the authenticated FastAPI multipart route. FastAPI still maps some unexpected face-camera exceptions to 502 with error detail; Spring proxies upstream failures using bounded generic errors.
- Web and Desktop login endpoints use in-memory per-remote-address throttling: 10 failed attempts per 15-minute window, with at most 10,000 client entries. State is process-local and resets on restart; it is not a shared/distributed quota. Login failures use generic responses. An external shared service Bearer protects FastAPI image/video/face processing routes; health remains unauthenticated. There is no general API quota/alerting, and proxy/network DoS resistance is unknown.
- Security audit events cover login success/failure, logout, password changes/resets, account lifecycle actions, gate-evidence reads/binding/recognition failures, preservation actions and cleanup summaries. CCCD QR success and handled scan failures are audited by the controller; unauthenticated and insufficient-role denials for the scan route are audited by the Web security chain. These events use content-free metadata and do not include the uploaded image or decoded CCCD values. Other framework/unhandled errors are not claimed as audited. Events contain actor/target/action/outcome and fixed failure reason; request secrets, hashes and tokens are not recorded by these paths.
- Spring H2 console is denied by the current filter chain; runtime reachability remains unverified.
