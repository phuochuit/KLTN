# Account-management override

`/account-management` + HTML live fragments; [MASTER](../MASTER.md) giữ toàn bộ tokens. Không redesign Desktop: trang Web này chỉ quản trị dữ liệu phiên/ca Desktop hiện đã có source.

## Lý do riêng
Trang dài nhiều miền, refresh HTML3 giây, form nhạy cảm và mật khẩu tạm chỉ hiển thị một lần; không được áp pattern auto-refresh lên tất cả trang.

- Chia sections bằng anchor “Tài khoản / Phiên hoạt động / Ca làm”, không tạo routes mới. Tài khoản bảng full-width, tạo/cập nhật form tập trung; sessions và shifts là regions riêng. Không Bento nhồi mỗi tài khoản thành tile.
- Temporary-password warning chỉ render khi model có giá trị; text về kênh an toàn và bắt buộc đổi, không biến thành toast tự mất. Không lưu lại vào draft/localStorage hoặc screenshot QA. Không tự gọi reset lại khi render thất bại.
- Profile modal giữ username/employee identity; labels/roleId/PII controls rõ. State/reset/revoke/delete shift là actions riêng, confirm cụ thể đúng đối tượng, native POST+CSRF và server grants. Không gộp reset với unlock hoặc đổi role.
- Giữ `/account-management/live`, `live-sessions`, `live-shifts` và trạng thái refresh riêng. Hiển thị thời điểm snapshot thành công; khi GET lỗi, giữ dữ liệu gần nhất, báo trạng thái cũ và đổi control thành “Thử lại”. Nút thử lại chỉ gọi GET hiện có, không replay POST. Refresh chỉ thay hai vùng live, không chạm form, profile dialog hay temporary secret. Giữ guard không overlap và pause khi document hidden.
- Khi control trong vùng live đang có focus, giữ fragment mới nhất chờ focus rời vùng; không thay DOM giữa thao tác. Nếu hộp thoại xác nhận đang mở thì tiếp tục defer để giữ nguyên form được xác nhận/CSRF. Polling vẫn 3 giây, không announce toàn bộ table mỗi tick.
- Danh sách ca nêu giới hạn 50 mục gần nhất; trạng thái phân biệt “Sắp diễn ra”, “Đang diễn ra”, “Đã kết thúc” theo timestamp hiện có. Xác nhận xóa chỉ rõ ca, nhân viên và giờ bắt đầu.
- Có thể mở trực tiếp vùng ca qua `#live-shifts`; không thêm route.
- Distinguish session “được ghi nhận đang hoạt động” với online sensor; lastSeenAt hiển thị, không hứa tức thời đã logout trước response. Permission-denied hoặc hết phiên không chỉ giữ stale table im lặng.
- Live HTML có CSRF form fields mới: không strip khi parse/replace; event delegation/data-confirm phải tiếp tục hoạt động. Không đưa token ra telemetry, không hardcode token trong JS.

Acceptance Phase2: limited grants, temporary secret one-time, password reset/lock/profile/shift/revoke flows, keyboard không mất focus qua polling, hidden tab pause, stale/error/401, confirmation cancel đúng action. Group 3 đã browser-check stale/error và profile draft; vẫn chưa kiểm tra deferral khi focus bên trong live fragment, hidden-tab pause, permission/401 matrix và toàn bộ action matrix.

## FE1 finalization — design basis recorded before source edits (2026-10-29)

This section is the approved direction for the new user-authorized FE1 finalization Build. It is a proposal recorded **before changing application source**; implementation and visual evidence will be appended separately and may refine these decisions after rendered review.

- **Retain the LumiPark frame; simplify the account workspace.** Keep the existing shell, Be Vietnam Pro, blue–violet Glassmorphism 2.0 and the account hero's title/description/create entry. Remove the decorative “Hồ sơ → Vai trò → Trạng thái” sequence because it reads as a workflow although it is not one. Replace three standalone count cards and the repeated directory count with one compact, labeled summary in the directory header; counts remain explicitly scoped to the already loaded list. This gets the actual employee directory into view sooner without inventing metrics.
- **Make the directory the main working surface.** Keep a semantic full-width table on an opaque reading surface, with a labeled horizontal scroller on narrow screens and the employee/action column pinned. Do not turn rows into mobile cards or hide role/status/contact columns. Use a clear name-first hierarchy (about 16/24), table content and controls at 14/20, and 12/18 only for genuinely secondary metadata/badges; preserve wrapping for long Vietnamese names and values. Use the inherited shell/page colors rather than add another palette.
- **Separate identity from operation.** Keep “Cập nhật” as the single primary row action and lock/unlock/reset in one native disclosure labeled “Tác vụ”; do not implement an ARIA menu role or add bulk actions. Opening the profile editor closes any open row action disclosures before `showModal()`, so an inert-but-open menu cannot reappear after the editor closes. Preserve dialog Escape/backdrop/draft warning/focus-return behavior and all existing POST+CSRF forms.
- **Keep the profile editor contextual and legible.** Retain the employee identity/status header, grouped fieldsets and right-side desktop dialog/full-width mobile dialog. Set labels to the shared 14/20 role and controls to a readable 16px input size with 44px minimum hit height; allow a single column when two fields cannot each retain the MASTER's 240px minimum. Draft/keep/discard and server flash outcomes remain distinct. Correct the misleading “Mật khẩu đã xác nhận” presentation to state only that an immediate change is not required; do not infer any stronger credential assurance.
- **Reuse proven controls.** Keep native `<select>` and the existing account-scoped `base-select` enhancement only where supported, with 44px popup options; keyboard focus and unsupported engines keep the native picker. Primary buttons keep the approved white-on-blue pairing across default/hover/pressed/focus/disabled/loading; secondary/destructive actions stay visually and semantically distinct. Consolidate FE1 declarations into one page-scoped rule set instead of adding another cascade layer. Do not alter the FE2 live regions, sessions, shifts or polling while doing so.

Alternatives rejected: preserving decorative step art and separate count tiles (extra vertical competition/redundancy), replacing the table with a card wall (slower cross-account comparison), a custom JavaScript menu/combobox (unneeded keyboard/state surface), and shared/global restyling (unapproved impact on Group 4A). UX research and the pre-edit baseline observations are recorded in [`RESEARCH.md`](../RESEARCH.md).

## Account Directory & Profile Editor refinement — G4B-ACC-FE1 (2026-10-29; pre-build basis)

This newly authorized design pass supersedes the prior FE1 directory/editor presentation decisions in §§70–80 for these two areas only. It does not reopen the account security boundary, change other account sections, or imply user acceptance. The new proposal was recorded before editing application source; research provenance and search limitations are in [`RESEARCH.md`](../RESEARCH.md).

- **Give the table a direct scan path.** Keep one semantic table and all existing account information/actions, with columns for employee, contact, role, account status and actions. Put the action group in its own final column so its context is explicit; retain “Cập nhật” as the primary action and keep lock/unlock and reset separate under the existing native “Tác vụ” disclosure and POST+CSRF forms. Do not add bulk actions, row navigation or client-side permission assumptions.
- **Reduce row height without hiding useful data.** Keep the full name first, combine username and employee code into concise secondary metadata that can wrap, and avoid a stacked identifier badge or a repeated decorative avatar with no real photo/identity data. Render the password-change reminder only when a change is required; the repeated “Không yêu cầu đổi mật khẩu” state is not useful row-by-row. Preserve the enabled/locked label and role as explicit table values. Keep the loaded-list scope and existing search/filter behavior.
- **Keep mobile as a table.** Preserve every column in a labeled horizontal scroller, keep the employee identity column pinned, and make the scroll guidance name the right-edge actions as well as the other columns. Do not turn the table into duplicate mobile cards or conceal a field based on breakpoint. Use the inherited colors/materials, visible focus, wrapping and touch-sized actions; avoid fixed row heights.
- **Make editor intent explicit.** Replace the text glyph close button with the locally built Lucide `x.svg`, marked decorative inside a native button with the existing accessible close name, visible focus and a 44px target. Add an explicit “Hủy” button that uses the same close request as the X, Escape and backdrop. Unchanged close returns directly; any dirty close presents the existing keep/discard guard, and discard/close returns focus to the invoking row action.
- **Align draft and save states.** Show distinct unchanged, dirty and saving messages. Disable “Lưu thay đổi” while unchanged, enable it when the current form differs from its loaded baseline, and expose a stable disabled/busy state after a valid submission. A no-change submit must not post. Keep the existing form fields, route, server validation, flash outcome and draft-leave protection; do not promise recovery after navigation/session loss or add a client-side persistence mechanism.
- **Keep the mobile editor fields unobscured.** Retain the sticky action footer on desktop, but return it to normal document flow at the narrow-screen breakpoint. The actual rendered mobile capture showed the footer covering the Email label at the initial scroll position; scrolling the form to reach actions is preferable to overlaying required inputs. Preserve full-width, touch-sized Cancel/Save actions after the form; do not shrink or hide fields to preserve a sticky bar.

Alternatives rejected: keep actions embedded below employee details (continues to inflate the identity cell and obscures the action hierarchy); replace the semantic table with responsive cards (duplicates/hides table relationships and conflicts with MASTER); remove account identifiers or the explicit enabled/locked state (loses useful information); leave save enabled for a no-op (invites unnecessary writes); create a separate cancel behavior that bypasses the existing draft guard; or retain a sticky mobile action bar that obscures fields. ## Tác vụ dropdown — G4B-ACC-FE1 final fix (2026-10-29; pre-build basis)

The current row-action `<details>` placed its action panel in ordinary table flow, so opening it increased that account row's height. No reusable popover component exists in the Spring Web source. Keep the compact row disclosure, but render its actions through a native `popover="auto"` opened by a declarative button/popover relationship. This uses the browser top layer rather than changing table geometry or escaping overflow with an unrelated portal; auto popovers provide outside-click/Escape dismissal and replace another open auto popover. Keep the two existing POST+CSRF forms and confirmation metadata unchanged.

Use the native invoker relationship and ordinary button/form controls rather than `role="menu"`: the actions include form submission and retain normal Tab navigation, while MASTER §7 requires the full Arrow/Home/End/Escape pattern if a menu role is used. Synchronize the visible disclosure state and retain focus return on keyboard dismissal. Position the top-layer panel from the trigger using viewport coordinates, flip above when needed, clamp both axes, and recalculate during page/table scrolling and resizing; close if its trigger leaves the viewport. This avoids relying on newer CSS anchor-positioning support for the required first/last-row and mobile placement.

The local UI UX Pro Max searches provided general overflow/table and focus prompts but no dependable popover-placement recipe; follow-up results were generic. The implementation basis is therefore LumiPark MASTER §§7, 8, 11 and rendered browser observation, plus the official [MDN Popover API guide](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using) and [popover attribute reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/popover). MDN documents the top layer, auto light dismissal, implicit invoker relationship/focus navigation and the one-auto-popover behavior. The selected position is custom page-local JavaScript; MDN does not certify its implementation or this page's accessibility.

### Chosen direction before Build

- **Operations, not online monitoring.** Organize the session area around separate Desktop and Web channels on near-opaque data surfaces. Show account, device where available, recorded login/last-activity times, current shift/task where available and the existing revoke action. Replace “Trực tuyến”/“đang đăng nhập” claims with wording that says a session is *được hệ thống ghi nhận*; say explicitly that this does not prove the person is currently at the device. Disclose the Desktop 100-record query limit and the Web SessionRegistry source without promising an exhaustive live-user inventory. Empty states must describe recorded data, not whether staff are physically working.
- **One truthful snapshot timeline.** Keep the 3-second same-origin GET, no-overlap guard, hidden-document pause/resume and GET-only retry. Visually distinguish checking, latest received while interaction is in progress, last displayed snapshot, stale network/server data, session expiry and access denial. Do not advance the displayed-snapshot time while either region is still showing an older snapshot. Retain the last displayed data and time for transient network/5xx failures; distinguish a thrown network failure from an HTTP failure. A 401/login redirect goes to the existing login route. A 403 clears live session/shift rows, stops automatic retries and offers a page reload to re-evaluate current access; it is not presented as an empty result.
- **Atomic, focus-safe fragment application.** Treat sessions and shifts as one pending snapshot. If any native dialog is open or focus is within either live region, keep only the newest response pending and do not replace either fragment. When the dialog closes, apply after all dialogs are closed; if a revoked-session action had focus, restore it to the equivalent action in the new snapshot, or to the affected channel heading when that row is gone. Without a modal, wait until focus leaves the live region. The status timestamp describes rows currently displayed, not merely fetched. Page-local lifecycle handling avoids changes to shared `app-dialog.js`; no CSRF/token, form submitter, POST, or temporary-secret behavior is copied into storage or logs.
- **Shift assignment stays a focused native form.** Keep the current username, shift name, start/end, duty and optional notes fields, `/account-management/shifts` POST, and CSRF field. Clarify that entered local times are Vietnam time, and validate start-before-end plus the existing 24-hour maximum with a field-linked message. Do not client-claim overlap/eligibility checks: those remain server-owned, and existing flash messages remain the outcome. Keep recent shifts as a semantic full table with employee, named shift, start/end, duty/notes, explicit upcoming/current/ended state and the existing delete confirmation identifying the affected assignment. State the 50-item limit; do not add auto-scheduling, approvals or calendar workflows.
- **Responsive LumiPark treatment.** Use inherited blue–violet and Be Vietnam Pro tokens: a restrained glass/chrome outer grouping, opaque table/form reading surfaces, strong hierarchy and stable row geometry. Keep every business column; label and make horizontal table scrollers keyboard reachable, with visible mobile scroll guidance. Stack content naturally on narrow screens rather than duplicating tables as cards. Keep date controls native, labels associated and action/focus states visible. No animation or color-only state cue is needed.

Research sources used for behavior, not as UI recipes: [MDN `HTMLDialogElement` close event](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/close_event) notes that `close` does not bubble, so listeners must attach to each dialog; [MDN `showModal()`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal) describes modal inertness; [MDN `fetch()`](https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch) distinguishes network rejections from HTTP error responses; [MDN `visibilitychange`](https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event) recommends stopping background UI updates while hidden. These sources support platform behavior only, not an accessibility-conformance claim.
